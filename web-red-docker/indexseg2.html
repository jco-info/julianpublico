Práctica de Redes en Docker

Enrutamiento entre dos LANs con routers Linux en contenedores

Realizado por JulianCO · SEGURIDAD ASIR

🎯 Introducción y objetivo

En esta práctica vamos a montar una red completa con 4 contenedores Docker: dos PCs (clientes) y dos routers Linux. El objetivo es que los dos PCs se comuniquen entre sí a través de los dos routers, simulando una topología clásica de dos LANs unidas por un backbone.

Topología

Contenedores y direcciones

Contenedorred-201red-202red-200Ruta por defecto
ord-201192.168.201.2——via 192.168.201.1
ord-202—192.168.202.2—via 192.168.202.1
router1192.168.201.1—192.168.200.1via 192.168.200.2
router2—192.168.202.1192.168.200.2via 192.168.200.1
¿Por qué usamos Docker? Docker crea bridges Linux reales, no simulaciones. Los contenedores usan la pila TCP/IP del kernel, así que el enrutamiento es real. Es mucho más ligero y rápido que montar 4 máquinas virtuales.

⚙️ Preparación del sistema

Toda esta preparación se hace en un Ubuntu Server recién instalado. Se hace una sola vez.

1. Actualizar el sistema e instalar dependencias

sudo apt update && sudo apt upgrade -y
sudo apt install -y ca-certificates curl gnupg lsb-release

Qué esperar: el sistema se actualiza y se instalan las dependencias básicas. Al final vuelve al prompt sin errores.

2. Instalar Docker (método oficial)

2.1 — Añadir la clave GPG

sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

2.2 — Añadir el repositorio

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

2.3 — Instalar Docker

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
Nota: si Ubuntu 26 aún no tiene repositorio stable para su nombre en clave (p. ej. plucky), usa $(lsb_release -cs) y, si falla, prueba con noble.

3. Añadir tu usuario al grupo docker

Así podrás usar docker sin sudo.

sudo usermod -aG docker $USER
newgrp docker

4. Habilitar IP forwarding en el host

Es recomendable que el host también tenga el forwarding activo.

sudo sysctl -w net.ipv4.ip_forward=1
echo "net.ipv4.ip_forward=1" | sudo tee /etc/sysctl.d/99-docker-forward.conf

Qué esperar: el comando devuelve net.ipv4.ip_forward = 1.

5. Verificar que todo funciona

docker run --rm hello-world

Qué esperar:

Hello from Docker!
This message shows that your installation appears to be working correctly.
docker network ls

Qué esperar: las 3 redes por defecto: bridge, host, none.

✅ Si ves el mensaje de hello-world, ya puedes empezar la práctica.

📦 Descargar la imagen onovillo/ubuntu-ssh

Antes de nada, comprobamos que la imagen existe y la descargamos.

docker pull onovillo/ubuntu-ssh

Qué esperar:

Using default tag: latest
latest: Pulling from onovillo/ubuntu-ssh
...
Status: Downloaded newer image for onovillo/ubuntu-ssh:latest
docker.io/onovillo/ubuntu-ssh:latest

✅ Imagen descargada.

1️⃣ Paso 1 — Crear las 3 redes

Vamos a crear 3 redes bridge con IPs fijas (sin DHCP).

docker network create \
  --driver=bridge \
  --subnet=192.168.200.0/24 \
  --ip-range=192.168.200.200/32 \
  --gateway=192.168.200.254 \
  red-200
docker network create \
  --driver=bridge \
  --subnet=192.168.201.0/24 \
  --ip-range=192.168.201.200/32 \
  --gateway=192.168.201.254 \
  red-201
docker network create \
  --driver=bridge \
  --subnet=192.168.202.0/24 \
  --ip-range=192.168.202.200/32 \
  --gateway=192.168.202.254 \
  red-202

Verificar que están creadas

docker network ls

Qué esperar:

NETWORK ID     NAME      DRIVER    SCOPE
xxxxx          bridge    bridge    local
xxxxx          host      host      local
xxxxx          none      null      local
xxxxx          red-200   bridge    local
xxxxx          red-201   bridge    local
xxxxx          red-202   bridge    local
Detalle importante:
• El gateway que pone Docker es .254, pero nadie lo usará (el router tiene .1). En el Paso 4 lo sobreescribiremos.
• El --ip-range=.../32 hace que Docker no asigne IPs automáticamente (solo reserva la .200). Así podemos poner IPs fijas sin conflictos.

2️⃣ Paso 2 — Lanzar los 4 contenedores

2.1 — Cliente ord-201 (red-201)

docker run -d --name ord-201 --network red-201 --ip 192.168.201.2 --privileged onovillo/ubuntu-ssh

2.2 — Cliente ord-202 (red-202)

docker run -d --name ord-202 --network red-202 --ip 192.168.202.2 --privileged onovillo/ubuntu-ssh

2.3 — Router 1 (red-201 + red-200)

docker run -d --name router1 --network red-201 --ip 192.168.201.1 --privileged onovillo/ubuntu-ssh
docker network connect --ip 192.168.200.1 red-200 router1

2.4 — Router 2 (red-202 + red-200)

docker run -d --name router2 --network red-202 --ip 192.168.202.1 --privileged onovillo/ubuntu-ssh
docker network connect --ip 192.168.200.2 red-200 router2

2.5 — Verificación

docker ps

Qué esperar: los 4 contenedores en Up, con la imagen onovillo/ubuntu-ssh y comando /usr/sbin/sshd -D.

3️⃣ Paso 3 — Verificar interfaces, rutas y forwarding

3.1 — Ver interfaces de cada contenedor

docker exec ord-201 ip -br a
docker exec ord-202 ip -br a
docker exec router1 ip -br a
docker exec router2 ip -br a

Qué esperar: cada PC con 1 interfaz, cada router con 2 interfaces.

ord-201:  eth0  192.168.201.2/24
ord-202:  eth0  192.168.202.2/24
router1:  eth0  192.168.201.1/24   eth1  192.168.200.1/24
router2:  eth0  192.168.202.1/24   eth1  192.168.200.2/24

3.2 — Ver rutas por defecto

docker exec ord-201 ip route
docker exec router1 ip route

Qué esperar: verás default via ...254 — una IP que no existe. Lo arreglaremos en el Paso 4.

3.3 — Verificar forwarding en los routers

docker exec router1 sysctl net.ipv4.ip_forward

Qué esperar: net.ipv4.ip_forward = 1 (o 0 según la imagen).

3.4 — Pings locales (deben funcionar)

docker exec ord-201 ping -c 2 192.168.201.1
docker exec router1 ping -c 2 192.168.200.2

✅ Deben dar 0% packet loss.

Ping entre LANs (debe fallar todavía)

docker exec ord-201 ping -c 2 192.168.202.2

❌ 100% packet loss. Todavía no hay enrutamiento entre LANs.

4️⃣ Paso 4 — Configurar rutas + IP forwarding

4.1 — Activar IP forwarding en los routers

docker exec router1 sysctl -w net.ipv4.ip_forward=1
docker exec router2 sysctl -w net.ipv4.ip_forward=1

Qué esperar: net.ipv4.ip_forward = 1 en cada uno.

4.2 — Corregir la ruta por defecto

docker exec ord-201 ip route replace default via 192.168.201.1
docker exec ord-202 ip route replace default via 192.168.202.1
docker exec router1 ip route replace default via 192.168.200.2
docker exec router2 ip route replace default via 192.168.200.1

Qué esperar: silencio. Sin errores = éxito.

4.3 — Verificar las rutas

docker exec ord-201 ip route

Qué esperar en ord-201:

default via 192.168.201.1 dev eth0
192.168.201.0/24 dev eth0 proto kernel scope link src 192.168.201.2

4.4 — Ping final: ord-201 → ord-202

docker exec ord-201 ping -c 4 192.168.202.2

Qué esperar:

PING 192.168.202.2 (192.168.202.2) 56(84) bytes of data.
64 bytes from 192.168.202.2: icmp_seq=1 ttl=62 time=0.123 ms
64 bytes from 192.168.202.2: icmp_seq=2 ttl=62 time=0.098 ms
64 bytes from 192.168.202.2: icmp_seq=3 ttl=62 time=0.105 ms
64 bytes from 192.168.202.2: icmp_seq=4 ttl=62 time=0.101 ms

--- 192.168.202.2 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss
Detalle clave: el ttl=62
Linux arranca el TTL en 64. Cada router que reenvía el paquete lo decrementa en 1. Si el TTL fuera 64, significaría que no ha atravesado routers (algo falla).

• TTL = 64 → 0 routers (misma red).
• TTL = 63 → 1 router.
• TTL = 62 → 2 routers (ida y vuelta pueden verse como 62 o 63 según cómo se cuente).

4.5 — Traceroute: ver el camino

Si traceroute no está instalado, lo instalamos con:

docker exec ord-201 sh -c "apt-get update && apt-get install -y traceroute"
Sintaxis correcta: usar sh -c "..." para que el && se ejecute dentro del contenedor. 
docker exec ord-201 traceroute 192.168.202.2

Qué esperar:

traceroute to 192.168.202.2 (192.168.202.2), 30 hops max, 60 byte packets
 1  router1.red-201 (192.168.201.1)  0.099 ms  0.015 ms  0.007 ms
 2  192.168.200.2 (192.168.200.2)    0.032 ms  0.011 ms  0.011 ms
 3  192.168.202.2 (192.168.202.2)    0.060 ms  0.014 ms  0.015 ms

Camino: ord-201 → router1 → router2 → ord-202. ✅

Conceptos dominados

  • Redes bridge en Docker → interfaces virtuales en el host.
  • IP fija sin DHCP → con --ip-range=/32.
  • Router Linux → contenedor con 2 interfaces.
  • IP forwarding → net.ipv4.ip_forward=1, imprescindible.
  • Ruta por defecto → ip route replace default via ....
  • TTL → cada router resta 1. Sirve para saber cuántos ha atravesado.
  • Traceroute → muestra el camino salto a salto.
🏁 Fin de la práctica

Has montado una red completa con 2 LANs, 2 routers y enrutamiento real entre extremos. Todos los conceptos que has aplicado (direccionamiento IP, tablas de rutas, forwarding, TTL) son exactamente los mismos que se usan en redes físicas reales.
