⚙️ Preparación de la máquina

Antes de empezar con Docker, hay que preparar Windows. Estos 4 pasos son obligatorios y se hacen una sola vez.

1. Comprobar la virtualización

Docker necesita que la virtualización esté activada en el procesador.

  1. Abre el Administrador de tareas (Ctrl + Shift + Esc).
  2. Ve a la pestaña Rendimiento → CPU.
  3. Busca abajo a la derecha "Virtualización".
Si dice "Habilitado": perfecto, pasa al paso 2.
Si dice "Deshabilitado": entra en la BIOS al reiniciar y activa Virtualization Technology, VT-x o SVM Mode.

2. Instalar WSL2

Docker en Windows funciona creando un pequeño Linux por dentro. Para eso Windows necesita WSL2.

  1. Busca PowerShell en el menú de inicio.
  2. Clic derecho → Ejecutar como administrador.
  3. Ejecuta:
wsl --install

Qué esperar: Windows descarga e instala WSL2. Al terminar, te pedirá reiniciar el ordenador. Hazlo.

3. Instalar Docker Desktop

  1. Ve a la página oficial: https://docs.docker.com/desktop/install/windows-install/
  2. Descarga Docker Desktop Installer.exe.
  3. Ejecútalo y sigue el asistente. Deja las opciones por defecto (asegúrate de que "Use WSL 2 based engine" esté marcada).

4. Verificar que todo funciona

  1. Abre Docker Desktop desde el menú de inicio. Espera a que el icono de la ballena se ponga verde.
  2. Abre PowerShell (ya no hace falta como administrador).
  3. Ejecuta:
docker run --rm hello-world

Qué esperar:

Hello from Docker!
This message shows that your installation appears to be working correctly.

✅ Si ves ese mensaje, ya tienes todo lo necesario para empezar.

📦 Bloque 1 — Imágenes y Contenedores

1.1 — Tu primer contenedor

Paso 1: Descargar la imagen de nginx

docker pull nginx

Qué esperar: verás varias líneas Pull complete y al final Status: Downloaded newer image for nginx:latest.

Paso 2: Listar imágenes locales

docker images

Qué esperar: aparece nginx en la columna REPOSITORY.

Paso 3: Ejecutar el contenedor

docker run -d --name mi-nginx -p 8181:80 nginx

Qué esperar: un hash largo (ID del contenedor).

Paso 4: Abrir en el navegador

Abre http://localhost:8181 → verás "Welcome to nginx!".

Paso 5: Acceder con curl desde otro contenedor

docker run --rm curlimages/curl http://mi-nginx

Qué esperar: error Could not resolve host: mi-nginx. La red bridge por defecto no resuelve nombres.

Obtén la IP del contenedor:

docker inspect --format='{{.NetworkSettings.Networks.bridge.IPAddress}}' mi-nginx

Qué esperar: algo como 172.17.0.2. Ahora usa esa IP:

docker run --rm curlimages/curl http://172.17.0.2

✅ Ahora sí responde el HTML de nginx.

Paso 6: Comprobar que el contenedor corre

docker ps

Qué esperar: fila con mi-nginx, Up X seconds, y 0.0.0.0:8181->80/tcp.

📝 Conclusión
  • La red bridge por defecto NO resuelve nombres de contenedores.
  • Solo funciona por IP. El DNS interno llega en el Ejercicio 3.2.
  • En Docker moderno, la IP está en NetworkSettings.Networks.<red>.IPAddress, no en NetworkSettings.IPAddress.

1.2 — Explorando el ciclo de vida

Paso 1: Detener el contenedor

docker stop mi-nginx

Qué esperar: devuelve mi-nginx.

Paso 2: Verificar el estado

docker ps

Qué esperar: tabla vacía (mi-nginx no aparece).

docker ps -a

Qué esperar: aparece mi-nginx con Exited (0) X seconds ago.

Paso 3: Volver a arrancarlo

docker start mi-nginx

Importante: start reutiliza el contenedor existente. No crea uno nuevo.

Paso 4: Reiniciarlo

docker restart mi-nginx

Diferencia: restart = stop + start.

Paso 5: Eliminarlo

docker stop mi-nginx
docker rm mi-nginx

Paso 6: Eliminar la imagen

docker rmi nginx

Qué esperar: varias líneas Untagged y Deleted.

📝 Conclusión
  • docker ps → solo los que corren.
  • docker ps -a → todos, incluidos los parados.
  • start ≠ run: start reutiliza, run crea.

1.3 — Inspeccionando contenedores

Paso 1: Crear contenedor interactivo con Alpine

docker run -it --name mi-alpine alpine sh

Qué esperar: prompt cambia a / #.

Paso 2: Dentro del contenedor

cat /etc/os-release
hostname

Paso 3: Salir

exit

Paso 4: ¿Sigue corriendo?

docker ps

Qué esperar: tabla vacía. No sigue corriendo.

¿Por qué? Un contenedor vive mientras vive su PID 1. Aquí el PID 1 era sh, y al hacer exit, se detiene.

Paso 5: Volver a entrar

docker start -ai mi-alpine

Crea un archivo para comprobar que el FS se conserva:

echo hola > /tmp/prueba.txt
exit

Paso 6: docker exec sobre contenedor parado

docker exec mi-alpine cat /tmp/prueba.txt

Qué esperar: error container ... is not running.

Arranca el contenedor y prueba de nuevo:

docker start mi-alpine
docker exec mi-alpine cat /tmp/prueba.txt

✅ Devuelve hola.

📝 Conclusión
  • Un contenedor vive mientras vive su PID 1.
  • El sistema de archivos se conserva entre stop y start.
  • docker exec requiere que el contenedor esté corriendo.

1.4 — Logs y depuración

Paso 1: Arrancar nginx como web

docker run -d --name web -p 8181:80 nginx

Paso 2: Generar tráfico

curl.exe http://localhost:8181

Repite varias veces o abre el navegador en http://localhost:8181.

Paso 3: Ver logs

docker logs web

Paso 4: Seguir logs en tiempo real

docker logs -f web

En otra ventana, haz curl.exe http://localhost:8181 y verás la línea aparecer.

Salir con Ctrl + C.

Paso 5: Extraer la IP

docker inspect --format='{{.NetworkSettings.Networks.bridge.IPAddress}}' web

O filtrando el JSON completo:

docker inspect web | Select-String "IPAddress"
📝 Conclusión
  • docker logs captura stdout/stderr del PID 1.
  • docker logs -f es como tail -f.
  • Los códigos HTTP en logs cuentan la historia: 200 OK, 304 caché, 404 not found.

💾 Bloque 2 — Volúmenes y Persistencia

Los contenedores son efímeros. Si quieres datos que sobrevivan, necesitas volúmenes.

2.1 — Los datos se pierden sin volúmenes

Paso 1: Crear contenedor Alpine

docker run -it --name sin-volumen alpine sh

Paso 2: Crear un archivo dentro

echo "datos importantes" > /datos.txt
cat /datos.txt
exit

Paso 3: Eliminar y crear otro

docker rm -f sin-volumen
docker run -it --name sin-volumen2 alpine sh

Paso 4: Buscar el archivo → no existe

cat /datos.txt

Qué esperar: can't open '/datos.txt': No such file or directory. 

exit
📝 Conclusión

Los datos dentro de un contenedor viven y mueren con él. Sin volumen, docker rm los destruye.

2.2 — Tu primer volumen nombrado

Paso 1: Crear volumen

docker volume create datos-persistentes
docker volume ls

Paso 2: Arrancar Alpine con el volumen

docker run -it --name c1 -v datos-persistentes:/data alpine sh

Paso 3: Escribir un archivo

echo "hola volumen soy JulianCO" > /data/archivo.txt
cat /data/archivo.txt
exit

Paso 4: Eliminar y recrear con el mismo volumen

docker rm -f c1
docker run -it --name c2 -v datos-persistentes:/data alpine sh

Paso 5: Verificar que el archivo sobrevive

cat /data/archivo.txt

✅ Devuelve hola volumen soy JulianCO.

exit
📝 Conclusión

Los volúmenes viven fuera del contenedor. Por eso los datos sobreviven al docker rm.

2.3 — Volúmenes anónimos y bind mounts

Parte A: Volumen anónimo

docker run -d --name nginx-vol -v /usr/share/nginx/html nginx
docker volume ls

Qué esperar: aparece un volumen con nombre hash (aleatorio). Ese es el anónimo.

Volumen anónimo: Docker lo crea automáticamente sin nombre. Vive asociado al contenedor.

Parte B: Bind mount con HTML propio

Crea la carpeta y el HTML en Windows:

mkdir $HOME\sitio-web
"<h1>Mi sitio local</h1>" | Out-File -Encoding utf8 $HOME\sitio-web\index.html

Arranca nginx montando esa carpeta:

docker run -d --name nginx-local -p 8082:80 -v ${HOME}/sitio-web:/usr/share/nginx/html:ro nginx

Abre http://localhost:8082 → verás "Mi sitio local".

Modifica el HTML en caliente:

"<h1>MODIFICADO en caliente - JulianCO</h1>" | Out-File -Encoding utf8 $HOME\sitio-web\index.html

Recarga el navegador (F5) → el cambio aparece al instante.

:ro = read-only. El contenedor puede leer, pero no escribir. Muy útil para configuraciones y HTML estático.
📝 Los 3 tipos de montaje
Tipo Sintaxis ¿Quién lo gestiona?
Volumen nombrado -v mi-vol:/ruta Docker
Volumen anónimo -v /ruta Docker (nombre hash)
Bind mount -v C:\ruta:/ruta Tú

2.4 — Persistencia con MySQL (caso real)

Paso 1: Crear volumen

docker volume create mysql-data

Paso 2: Arrancar MySQL 8

docker run -d --name mysql-db -v mysql-data:/var/lib/mysql -e MYSQL_ROOT_PASSWORD=secret123 -e MYSQL_DATABASE=prueba -p 3306:3306 mysql:8

Paso 3: Esperar a que arranque

docker logs -f mysql-db

Cuando veas ready for connections, pulsa Ctrl+C.

Paso 4: Crear tabla e insertar datos

docker exec -it mysql-db mysql -uroot -psecret123 -e "CREATE TABLE prueba.personas(id INT, nombre VARCHAR(50)); INSERT INTO prueba.personas VALUES (1, 'Ana');"
docker exec -it mysql-db mysql -uroot -psecret123 -e "SELECT * FROM prueba.personas;"

Qué esperar: la tabla con (1, Ana).

Paso 5: Eliminar y recrear con el mismo volumen

docker rm -f mysql-db
docker run -d --name mysql-db2 -v mysql-data:/var/lib/mysql -e MYSQL_ROOT_PASSWORD=secret123 -p 3306:3306 mysql:8

Espera unos segundos y comprueba que los datos siguen:

docker exec -it mysql-db2 mysql -uroot -psecret123 -e "SELECT * FROM prueba.personas;"

✅ ¡Los datos sobrevivieron al docker rm!

Paso 6: Inspeccionar el volumen

docker volume inspect mysql-data

Qué esperar: JSON con el campo Mountpoint.

📝 Conclusión

Los datos de MySQL no viven en el contenedor, viven en el volumen mysql-data. El contenedor MySQL es desechable; el volumen es el que persiste.

2.5 — Limpieza de volúmenes

Paso 1: Listar volúmenes

docker volume ls

Paso 2: Intentar borrar datos-persistentes

docker volume rm datos-persistentes

Qué esperar: error volume is in use - [<id>] porque c2 lo tiene montado.

Paso 3: Eliminar contenedor y volumen

docker rm -f c2
docker volume rm datos-persistentes

Paso 4: Limpiar volúmenes huérfanos

docker volume prune
Atención: docker volume prune solo borra volúmenes anónimos. Para borrar también los nombrados, usa docker volume prune -a o docker volume rm <nombre>.
📝 Conclusión
  • No se puede borrar un volumen en uso, ni siquiera por un contenedor parado.
  • prune solo borra anónimos no usados.
  • Para borrar nombrados: docker volume rm <nombre>.

🌐 Bloque 3 — Redes

3.1 — Redes por defecto

Paso 1: Listar redes

docker network ls

Qué esperar: bridge, host, none.

Paso 2: Arrancar dos Alpine en la red bridge

docker run -dit --name host1 alpine sh
docker run -dit --name host2 alpine sh

Paso 3: Obtener IP de host1

docker inspect --format='{{.NetworkSettings.Networks.bridge.IPAddress}}' host1

Qué esperar: algo como 172.17.0.3.

Paso 4: Ping por IP (funciona)

docker exec host2 ping -c 3 172.17.0.3

✅ 0% packet loss.

Paso 5: Ping por nombre (debe fallar)

docker exec host2 ping -c 3 host1

Qué esperar: ping: bad address 'host1'.

📝 Conclusión

La red bridge por defecto permite conectividad por IP, pero no resuelve nombres.

3.2 — Red personalizada con DNS interno

Paso 1: Crear red

docker network create mi-red

Paso 2: Inspeccionar la red

docker network inspect mi-red

Apunta la subred (algo como 172.18.0.0/16).

Paso 3: Arrancar dos contenedores en mi-red

docker run -dit --name h1 --network mi-red alpine sh
docker run -dit --name h2 --network mi-red alpine sh

Paso 4: Ping por nombre (¡funciona!)

docker exec h2 ping -c 3 h1

✅ Devuelve PING h1 (172.18.0.2). Docker ha resuelto el nombre.

📝 Conclusión

Las redes personalizadas tienen un DNS embebido. Cada contenedor se registra con su nombre y los demás lo resuelven.

3.3 — Conectar y desconectar contenedores

Paso 1: Crear db en mi-red

docker run -dit --name db --network mi-red alpine sh

Paso 2: Crear cliente sin red personalizada

docker run -dit --name cliente alpine sh

Paso 3: Ping (debe fallar)

docker exec cliente ping -c 2 db

Qué esperar: ping: bad address 'db'.

Paso 4: Conectar cliente a mi-red

docker network connect mi-red cliente

Paso 5: Ping (ahora funciona)

docker exec cliente ping -c 2 db

✅ Ahora responde.

Paso 6: Desconectar

docker network disconnect mi-red cliente

Paso 7: Ping otra vez (falla)

docker exec cliente ping -c 2 db
📝 Conclusión

Un contenedor puede estar en varias redes a la vez. El DNS solo funciona entre contenedores de la misma red.

3.4 — Nginx + Nginx (proxy reverso personalizado)

En este ejercicio vamos a montar un backend personalizado con tu nombre (JulianCO) y un proxy reverso que redirige a él usando DNS interno de Docker.

Nota: el profesor menciona una imagen mi-app:1.0 y Flask en el puerto 5000. Nosotros usamos nginx y el puerto 80, pero la idea es la misma: un backend personalizado servido detrás de un proxy.

Paso 1: Crear el HTML personalizado

mkdir $HOME\mi-web

Crea el archivo index.html dentro de C:\Users\<tu-usuario>\mi-web\ con este contenido:

<!DOCTYPE html>
<html>
<head>
    <title>Backend personalizado - JulianCO</title>
</head>
<body>
    <h1>Respuesta del BACKEND - JulianCO</h1>
    <p>Esta página ha sido personalizada por JulianCO.</p>
    <p>Servidor: nginx en contenedor Docker</p>
    <p>Red: mi-red</p>
</body>
</html>

O en una sola línea desde PowerShell:

"<!DOCTYPE html>...</html>" | Out-File -Encoding utf8 $HOME\mi-web\index.html

Verifica:

type $HOME\mi-web\index.html

Paso 2: Arrancar el backend personalizado

docker run -d --name backend --network mi-red -v ${HOME}/mi-web:/usr/share/nginx/html:ro nginx

Paso 3: Verificar que sirve el HTML personalizado

docker run --rm --network mi-red curlimages/curl http://backend

Qué esperar: el HTML con tu nombre:

<h1>Respuesta del BACKEND - JulianCO</h1>
<p>Esta página ha sido personalizada por JulianCO.</p>

✅ El backend ya sirve tu HTML.

Paso 4: Crear el nginx.conf del proxy

server {
    listen 80;
    location / {
        proxy_pass http://backend:80;
    }
}

Guárdalo como $HOME\nginx.conf o usa PowerShell:

"server {`n    listen 80;`n    location / {`n        proxy_pass http://backend:80;`n    }`n}" | Out-File -Encoding ascii $HOME\nginx.conf
Ojo: si dejas backend:5000 (como el profesor), el proxy dará 502 Bad Gateway porque nginx escucha en 80. Para que funcione, usa backend:80.

Paso 5: Arrancar el proxy

docker run -d --name proxy -p 8083:80 --network mi-red -v ${HOME}/nginx.conf:/etc/nginx/conf.d/default.conf:ro nginx

Paso 6: Probar el proxy

curl.exe http://localhost:8083

Qué esperar: el HTML con tu nombre (JulianCO). El proxy ha resuelto backend por DNS y ha redirigido.

✅ En el navegador: http://localhost:8083 → tu HTML personalizado.

Paso 7: Comprobar el aislamiento

docker network disconnect mi-red proxy
docker restart proxy
curl.exe http://localhost:8083

Qué esperar: 502 Bad Gateway o Empty reply from server. El proxy ya no resuelve backend.

Vuelve a conectarlo:

docker network connect mi-red proxy
docker restart proxy

✅ Vuelve a funcionar.

📝 Conclusión
  • proxy_pass http://backend:PUERTO → resuelve el nombre por DNS interno.
  • Sin --network mi-red, el proxy no puede resolver backend.
  • El 502 es la prueba visual de que el aislamiento funciona.

3.6 — Limpieza final

Paso 1: Eliminar todos los contenedores

docker rm -f $(docker ps -aq)

Paso 2: Eliminar redes sin uso

docker network prune

Pulsa y para confirmar. La red mi-red se borrará.

Paso 3: Eliminar volúmenes sin uso

docker volume prune
Ojo: solo borra volúmenes anónimos. Para borrar también los nombrados (mysql-data), usa: 
docker volume rm mysql-data

Paso 4: Ver el espacio usado

docker system df

Qué esperar: tabla con el espacio de imágenes, contenedores, volúmenes y build cache.

📝 Conclusión
  • docker rm -f $(docker ps -aq) → el "botón de reset".
  • prune solo borra lo que no está en uso.
  • Las redes bridge, host, none no se borran.
